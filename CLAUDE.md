# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server on port 5173 (strict port, exposed on the LAN so an iPad can connect). Also configured as `dev` in `.claude/launch.json`.
- `npm run build` — `tsc --noEmit && vite build`. Type-checking is the only static check; there is no linter.
- `npm test` — Vitest (jsdom), `src/**/*.test.ts`, next to the code they cover. Only logic without Phaser is tested: journey/series flow and data integrity (`stages.test.ts`), the town (`city/town.test.ts`), the barnyard rules (`minigames/barnyard/barnyardLogic.test.ts`), the forest's quests, director, motion and data (`minigames/forest/*.test.ts`), `forestSave`, `profile` (wallet), `stars`, the pizza check and translations. Data-integrity tests check that every texture key a table names is a file in `src/art` (`src/test/art.ts`), so a typo in a `DEFS`/`biomes`/`stages` row fails a test, not the player. Logic that should be tested goes in a module that does not import Phaser (that is why `motion.ts`, `director.ts`, `quests.ts`, `town.ts` and `pizzaData.ts` are separate); keep Phaser out of them.
- `npm run preview` — serve the production build (also `preview` in `.claude/launch.json`, port 4173).
- The latest commit's date/time and subject are injected at build/dev-start as `__BUILD_COMMIT__` (`define` in `vite.config.ts`, typed in `src/build-info.d.ts`) and shown faintly at the bottom of `Title`. In dev it only updates when the dev server restarts.
- Dev-only helpers: `window.__game` exposes the Phaser game instance; `?debug` in the URL shows an FPS counter.

## Workflow

- Always commit when you are done with a task (after `npm run build` and `npm test` pass). Don't wait to be asked.
- **Language rule:** all code is English, always, even though the game's player-facing text is Slovene and the conversation may be too. That covers identifiers, comments, file names, scene keys, journey ids, enum/union values, texture keys and `src/art/*.svg` file names, storage keys and commit messages (e.g. `forest-mushroom.svg`, not `gozd-gobec.svg`; `'city'`, not `'mesto'`). The only Slovene allowed is in `src/i18n/sl.ts`, and it must never double as a key, id or texture name. If a Slovene word shows up in code, rename it. The product name "Mesto" is the one exception: it is a brand name (manifest, `index.html`, package name, title screen).
- `W`/`H` (the design size) live in `src/core/layout.ts`; `src/main.ts` only builds the Game, so scenes can read them anywhere.
- Storage goes through `src/core/storage.ts` (`readItem`/`writeItem`/`readJson`/`writeJson`), never `localStorage` directly.

## Architecture

Phaser 4 + TypeScript + Vite kids' game targeting iPad (installable via `public/manifest.webmanifest`). The game uses a fixed 2048×1536 canvas (`W`, `H` from `src/core/layout.ts`) scaled with `Phaser.Scale.FIT`; lay everything out in those coordinates. Player-facing text is Slovene by default with an English translation, managed by the i18n module (see **Translations** below).

**Scenes** (`src/scenes/registry.ts`): the single list of scenes, keyed by class name (the same string the class passes to `super()`). `main.ts` registers `Object.values(scenes)` and `SceneKey` is the only type that may name a scene (`Stage.scene`, `hubScene()`, `advanceFlow()`), so a typo fails `tsc`. A new scene is added there, not in `main.ts`.

**Journeys and stages** (`src/core/stages.ts`): the game is data-driven. A `Journey` is an ordered list of `Stage`s (`{id, scene, icon, label, data?}`; `id` is unique within its journey), and the module-level `progress` object holds the current journey, stage index, the best stars won per stage (`progress.earned`, read with `starsEarned()`/`totalStars()`, written by `bankStars()`) and the fish choice. Coins and the pet are not there: they live in `core/profile.ts`. Flow: `Title` → "Play" starts the `city` journey (its hub); "Minigames" → `GameSelect`, a scrolling grid with one card per stage of the city journey (`startSolo()` in `stages.ts` = walking into that door via `enterStage()`, with `progress.solo` set so that leaving, finishing or ◀ returns to the list, not the town; series show their own `StageMap` first). Plain journeys: `StageMap` (shows stages, "Go!" starts the scene of `stages[progress.index]`, passing `data`) → stage scene → back to `StageMap`. To add a stage: write a scene, register it in `src/scenes/registry.ts`, and add an entry to the journey. To add a journey: extend `JourneyId` and `journeys`; it is played as a series from a city door. A new city stage appears in `GameSelect` by itself.

**Stage scenes** extend `StageScene` (`src/core/MiniGame.ts`); a scene ends a successful play with `this.win(stars, {message?, ms?})`: one banner + the earned stars + one jingle, then `finish(stars)`, which banks the stars (best per stage, so replays cannot inflate them), increments `progress.index` and fades to `advanceFlow()` (`stages.ts`): the `StageMap`, or, once the last stage of a plain journey is done, back to where it was started (the hub when it was a series, else `GameSelect`). There are no finale scenes; the last stage just returns. Every stage scene has the ◀ button (`backdrop()`; override `onBack()` to bank something first): back to the hub, the series map or the journey's `StageMap`; `StageMap` has ◀ too (series → hub, plain journey → `GameSelect`), and `GameSelect` goes back to `Title`. Journey ids are `food`, `city`, `farm`, `octopus`; the forest and the pizzeria are single stages (`ForestRun`, `PizzaMaker`) of the city, not journeys. Minigames live in `src/scenes/minigames/`; the same scene can be reused with different `data` (e.g. `FarmShoot` with different `animals`/`goal`, `FishCut` with `items`).

**City journey** (`src/scenes/CityHub.ts` plus `src/scenes/city/`): `city/town.ts` is the town as data (sizes, `spots`, `northZones`, and `isBlocked()` for walking, no Phaser), `city/draw.ts` is `TownView`, which draws the whole town once and returns its `walls` and `doors`, and `CityHub` is only the controller (player, pet, HUD, joystick, doors). a `Journey` may set `hub` (here `'CityHub'`) to replace the `StageMap`; `hubScene()` in `stages.ts` is where `GameSelect` and `StageScene.finish()` go. Hub journeys are free roaming: `finish()` does not advance `progress.index` (stars are keyed by the door, `progress.building`), every stage can be entered in any order and any number of times, and there is no finale. The first time a player goes through the forest gate (no record yet) it opens `ForestShop` first (`enterStage()` in `stages.ts`). `CityHub` is a 3/4 ("45°") view of a 6300×2300 town (the world also reaches 2400 px above y=0): buildings show front wall + roof, every object's depth is its ground `y`, the camera follows the player, and the left-bottom joystick (or arrows/WASD) moves them, sliding along rectangle `walls`. The `spots` array has one entry per stage of the journey, matched by stage `id` (add a stage + a spot with the same `id` to add a building). Walking into a door starts that stage; `progress.building` (a stage `id`) remembers which door you left from. `spots` match stages by `id`, not by position. The pet bought in `PetShop` (`progress.petOwned`) follows the player, and the ⌂ button leaves to `Title`.

The town has two exits. North of the street the player may only walk in `northZones` (`PATH`, a dirt path between two top-row buildings, and `CLEARING`); it ends at a forest gate (`kind: 'gate'` spot) that starts `ForestRun`. East, the street becomes a dirt country road to a farm yard (x from `FARM_X`, down to `YARD_END`) with two rows of buildings: the barn (`EggCollect`), the hen house (the `farm` series) and the cow shed (`CowMilk`) on top, the pig sty (`PigFeed`), the sheep pen (`SheepShear`) and the rabbit hutch (`RabbitFeed`) below. Those four live in `src/scenes/minigames/barnyard/`: milk a cow by tapping its udder until the jug is full, shear a sheep by dragging over its wool tufts, feed pigs apples dragged from a basket and tap a fat one for a ham, tap rabbits that pop out of burrows to throw them a carrot. Their rules (jug level, pig size, tuft grid, swipe distance) are Phaser-free in `barnyardLogic.ts`. Hens, pigs, sheep, cows and bunnies wander in the yard between the rows (`YARD_WALK`).

**Series** (`Stage.series`): a hub stage may play a whole other journey (own `StageMap` and stages) and then return to the hub. The stage has `scene: 'StageMap'` and `series: <JourneyId>`; `CityHub.enter()` calls `startSeries()`, which sets `progress.sub` (so `currentJourney()` is the series, `StageMap` shows a ◀ button to leave early; `Journey.catch` makes `FishCut` cut the octopus there, via `currentCatch()`, instead of the fish picked in the shop). When a series' last stage finishes, `advanceFlow()` calls `endSeries()` and returns the hub scene. The octopus journey is only reachable this way (a house in the city); the food and farm journeys are a series too (a house and the hen house).

**Forest** (`src/scenes/minigames/forest/`): endless first-person shooter on a forest path. It is pseudo-3D done by hand: entities have world `x`/`z`, `proj()` (`projection.ts`) maps them to the screen (`s = FOCAL/(FOCAL+z)`, depth = `-z`), and the path is redrawn each frame into a Graphics. `ForestRun.ts` is the scene (input, shooting, update loop, entities, end of run) and delegates to: `state.ts` (`RunState`/`Ent`: everything that changes in a run, created fresh by `newRun()` in `create()`, so "Play again" needs no manual reset: put new per-run numbers there, not on the scene), `quests.ts` (`QuestLog`, no Phaser), `director.ts` (`chooseSpawn`/`spawnInterval`, no Phaser), `motion.ts` (`stepMotion`, no Phaser), `boss.ts` (the demon), `backdrop.ts` (sky, ground, worlds, weather), `hud.ts` and `endScreen.ts`. Enemy/item stats, quest templates and how things move live in `forestData.ts`: `Def.move` (`homing`, `sway`, `bob`, `hop`, `drift`, `drop`) describes a monster's movement as data, so a new ordinary monster is one `DEFS` row plus art, a bag entry in `biomes.ts` and a quest key; only the troll's throws and the demon have code (`Def.boss`/`Def.solid`/`Def.tint` flag bosses, un-shootable fireballs and re-tinted art); art is `src/art/{forest,cave,arctic,hell}-*.svg` and `fireball.svg`. Left-bottom joystick strafes, any other tap shoots at that point (hold to keep firing with auto weapons).

The run passes through four **worlds** by distance (`biomes.ts`: forest 0 m, cave 250, arctic 600, hell 1000). A `Biome` holds the sky/ground gradients, path colours, decor, spawn `bag`, quest pool and weather; `ForestBackdrop.setBiome()` crossfades to the next one (`ForestRun.enterBiome()` then drops quests that can't be done there via `QuestLog.adaptTo()`). In hell the demon (`BOSS_AT_M`) hovers at `BOSS_Z` (`boss.ts`), swings left and right and throws fireballs along three lanes that can only be dodged (it turns red just before a volley); killing it calls `victory()`. Dev only: `?m=1150` starts the run that many metres in.

**Weapons and coins** (`forest/weapons.ts`, `forest/ForestShop.ts`, `src/core/forestSave.ts`): `WEAPONS` defines pistol/shotgun/smg/laser/rocket (damage, magazine, reload, cooldown, `mode` nearest|splash|pierce, `auto`). There is one persistent wallet for the whole game, `profile` (`core/profile.ts`, localStorage `profile`: coins, pet; `earn()`/`spend()`): Checkout, the farm and the forest earn into it, the pet shop and the weapon shop spend from it. `forestSave` (`forest-save`) keeps only the owned weapons, the equipped one, the best distance and a run counter (the first 3 runs show longer hints). `profile` takes over the coins an old `forest-save` held. `ForestShop` always goes on to `ForestRun`; it is opened by the gate's first visit and from the end-of-run screen.

**Pizzeria** (`PizzaMaker`, `src/scenes/minigames/pizzaData.ts`): `PizzaMaker` serves 3 customers. The pizzas are real ones from the Harlekin inn menu (harlekin.si); the ones not added yet, and what ingredient each still needs, are in `TODO-pizzas.md`. A pizza is stacked 500×500 layer textures `pizza-<ingredient>` on `pizza-dough`; the customer's order bubble is built from the same layers. `check()` requires sauce then cheese first, then exactly the toppings in any order; a wrong pizza repeats the same customer.

**Translations** (`src/i18n/`): `en.ts` is the source of truth, a flat `as const` object of English-keyed strings (`'quest.bear': '🐻 Defeat bears {n}'`) and `type Key = keyof typeof en`; `sl.ts` is `Record<Key, string>`, so a missing translation fails `tsc`. `t(key, { n })` fills `{name}` placeholders. Never write player-visible text inline in a scene: add a key to both files (namespaced by area: `stage.*`, `quest.*`, `forest.*`, ...) and call `t()` inside `create()`/methods, not at module top level (the language is read at startup and can change on the Title screen). Data tables store keys, not text (`Stage.label` and `Journey.title` are `Key`s; pizza names are `pizza.${id}`), and are translated where rendered. The language comes from `?lang=sl|en` (remembered), then localStorage `lang`, then Slovene; the corner button on `Title` switches it and restarts the scene. To add a language: extend `Lang`/`LANGS` in `index.ts`, add a `Record<Key, string>` table. No plural helper yet: add one when a string needs a real count.

**Assets**: there are no image or audio files to load by hand. Every SVG in `src/art/` is auto-loaded by `Boot` (via `import.meta.glob`) as a texture keyed by its filename without extension (`src/art/monster.svg` → `'monster'`), rasterised at scale 1.5. Sound is synthesised with WebAudio in `src/core/sfx.ts`; `unlockAudio()` must be called from a user tap (iOS rule).

**Shared HUD and rules** (`src/core/ui.ts`, `stars.ts`): `hudTitle` (title at the top, optional fade), `counter(scene, goal)` ("n / goal" under it), `coinCounter` (the wallet, top-right, same coin everywhere), `starRow`, and double-tap-guarded buttons. `starsFor(misses)` (`stars.ts`) is the one star rule: 3 = ≤2 misses, 2 = ≤5, 1 otherwise; games that cannot be played badly give 3. The forest's stars are `forestStars()`, banked the moment a run ends. Kitchen scenery shared by `Cook`/`FishCut`/`PizzaMaker` is in `minigames/kitchen.ts`. Do not hand-roll titles, counters, coin icons, win text or yay sounds in a scene.

**Touch and UI helpers** (`src/core/`): `touch.ts` has `dragX`, `tapButton`, `text` (large, forgiving touch targets, consistent styling). `ui.ts` has `circleButton` (the round back/home button) and `outlined` (ink-outlined HUD text). `Joystick.ts` is the one touch stick plus arrow keys/WASD (fixed, or floating under the finger with no `x`/`y`; `axis: 'x'` for strafing): create it in `create()`, read `joy.read()` each frame, and call `joy.owns(p)` in your own `pointerdown` so the stick's finger doesn't also act as a tap. `theme.ts` holds the shared colours (`INK`, `CREAM`, `FADE_RGB`) and `FONT`: don't write those literals in scenes. `GameScene.ts` is the base for scenes that fade: `fadeInScene(bg)` in `create()` and `fadeToScene(key | () => key, data?, ms?)` to leave; `StageScene` builds on it. Input supports 3 simultaneous pointers.

**No offline mode**: the game used to precache everything with a service worker, but that kept serving stale builds after a new deploy, so it was removed. `public/sw.js` is only a kill switch for devices that still have the old worker (it clears caches and unregisters itself), and `src/main.ts` also unregisters leftovers. Do not register a service worker again.

**Deploy**: `.github/workflows/deploy.yml` builds and publishes `dist/` to GitHub Pages on every push to `main` (repo Settings → Pages → Source must be "GitHub Actions"). Pages serves project sites from `/<repo>/`, so the build uses `base: './'` and every URL (index.html links, manifest) must stay relative; never add root-absolute (`/foo`) URLs.
