# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server on port 5173 (strict port, exposed on the LAN so an iPad can connect). Also configured as `dev` in `.claude/launch.json`.
- `npm run build` — `tsc --noEmit && vite build`. Type-checking is the only static check; there is no linter or test suite.
- `npm run preview` — serve the production build (also `preview` in `.claude/launch.json`, port 4173).
- The latest commit's date/time and subject are injected at build/dev-start as `__BUILD_COMMIT__` (`define` in `vite.config.ts`, typed in `src/build-info.d.ts`) and shown faintly at the bottom of `Title`. In dev it only updates when the dev server restarts.
- Dev-only helpers: `window.__game` exposes the Phaser game instance; `?debug` in the URL shows an FPS counter.

## Workflow

- Always commit when you are done with a task (after `npm run build` passes). Don't wait to be asked.
- **Language rule:** all code is English, always, even though the game's player-facing text is Slovene and the conversation may be too. That covers identifiers, comments, file names, scene keys, journey ids, enum/union values, texture keys and `src/art/*.svg` file names, storage keys and commit messages (e.g. `forest-mushroom.svg`, not `gozd-gobec.svg`; `'city'`, not `'mesto'`). The only Slovene allowed is in `src/i18n/sl.ts`, and it must never double as a key, id or texture name. If a Slovene word shows up in code, rename it. The product name "Mesto" is the one exception: it is a brand name (manifest, `index.html`, package name, title screen).
- `W`/`H` (the design size) live in `src/core/layout.ts`; `src/main.ts` only builds the Game, so scenes can read them anywhere.
- Storage goes through `src/core/storage.ts` (`readItem`/`writeItem`/`readJson`/`writeJson`), never `localStorage` directly.

## Architecture

Phaser 4 + TypeScript + Vite kids' game targeting iPad (installable via `public/manifest.webmanifest`). The game uses a fixed 2048×1536 canvas (`W`, `H` from `src/core/layout.ts`) scaled with `Phaser.Scale.FIT`; lay everything out in those coordinates. Player-facing text is Slovene by default with an English translation, managed by the i18n module (see **Translations** below).

**Scenes** (`src/scenes/registry.ts`): the single list of scenes, keyed by class name (the same string the class passes to `super()`). `main.ts` registers `Object.values(scenes)` and `SceneKey` is the only type that may name a scene (`Stage.scene`, `hubScene()`, `advanceFlow()`), so a typo fails `tsc`. A new scene is added there, not in `main.ts`.

**Journeys and stages** (`src/core/stages.ts`): the game is data-driven. A `Journey` is an ordered list of `Stage`s (`{id, scene, icon, label, data?}`; `id` is unique within its journey), and the module-level `progress` object holds the current journey, stage index, stars, coins and chosen pet. Flow: `Title` → `GameSelect` (pick a journey, calls `startJourney`) → `StageMap` (shows stages, "Go!" starts the scene of `stages[progress.index]`, passing `data`) → stage scene → back to `StageMap`. To add a stage: write a scene, register it in `src/scenes/registry.ts`, and add an entry to the journey. To add a journey: extend `JourneyId`, `journeys`, and the `cards` list in `src/scenes/GameSelect.ts`.

**Stage scenes** extend `StageScene` (`src/core/MiniGame.ts`); calling `finish(stars)` awards stars, increments `progress.index`, and fades to `advanceFlow()` (`stages.ts`): the `StageMap`, or, once the last stage of a plain journey is done, back to where it was started (the hub when it was a series, else `GameSelect`). There are no finale scenes; the last stage just returns. Journey ids are `food`, `city`, `farm`, `octopus`, `forest`, `pizza`. Minigames live in `src/scenes/minigames/`; the same scene can be reused with different `data` (e.g. `FarmShoot` with different `animals`/`goal`, `FishCut` with `items`).

**City journey** (`src/scenes/CityHub.ts`): a `Journey` may set `hub` (here `'CityHub'`) to replace the `StageMap`; `hubScene()` in `stages.ts` is where `GameSelect` and `StageScene.finish()` go. Hub journeys are free roaming: `finish()` does not advance `progress.index`, every stage can be entered in any order and any number of times, and there is no finale. `StageScene.backdrop()` adds a back button (top-left) that returns to the hub without finishing. `CityHub` is a 3/4 ("45°") view of a 6300×2300 town (the world also reaches 2400 px above y=0): buildings show front wall + roof, every object's depth is its ground `y`, the camera follows the player, and the left-bottom joystick (or arrows/WASD) moves them, sliding along rectangle `walls`. The `spots` array has one entry per stage of the journey, matched by stage `id` (add a stage + a spot with the same `id` to add a building). Walking into a door starts that stage; `progress.building` (a stage `id`) remembers which door you left from. `spots` match stages by `id`, not by position. The pet bought in `PetShop` (`progress.petOwned`) follows the player, and the ⌂ button leaves to `GameSelect`.

The town has two exits. North of the street the player may only walk in `northZones` (`PATH`, a dirt path between two top-row buildings, and `CLEARING`); it ends at a forest gate (`kind: 'gate'` spot) that starts `ForestRun`. East, the street becomes a dirt country road to a farm yard with a barn (`EggCollect`) and a hen house (the `farm` series).

**Series** (`Stage.series`): a hub stage may play a whole other journey (own `StageMap` and stages) and then return to the hub. The stage has `scene: 'StageMap'` and `series: <JourneyId>`; `CityHub.enter()` calls `startSeries()`, which sets `progress.sub` (so `currentJourney()` is the series, `StageMap` shows a ◀ button to leave early; `Journey.catch` makes `FishCut` cut the octopus there, via `currentCatch()`, instead of the fish picked in the shop). When a series' last stage finishes, `advanceFlow()` calls `endSeries()` and returns the hub scene. The octopus journey is only reachable this way (a house in the city); the food and farm journeys are a series too (a house and the hen house) and, like forest and pizza, are also listed in `GameSelect`.

**Forest journey** (`ForestRun`, `src/scenes/minigames/forestData.ts`): endless first-person shooter on a forest path. It is pseudo-3D done by hand: entities have world `x`/`z`, `proj()` maps them to the screen (`s = FOCAL/(FOCAL+z)`, depth = `-z`), and the path is redrawn each frame into a Graphics. Enemy/item stats and quest templates live in `forestData.ts` (`Def.boss`/`Def.solid`/`Def.tint` flag bosses, un-shootable fireballs and re-tinted art); art is `src/art/{forest,cave,arctic,hell}-*.svg` and `fireball.svg`. Left-bottom joystick strafes, any other tap shoots at that point (hold to keep firing with auto weapons).

The run passes through four **worlds** by distance (`biomes.ts`: forest 0 m, cave 250, arctic 600, hell 1000). A `Biome` holds the sky/ground gradients, path colours, decor, spawn `bag`, quest pool and weather; `ForestRun.setBiome()` crossfades to the next one and drops quests that can't be done there. In hell the demon (`BOSS_AT_M`) hovers at `BOSS_Z`, swings left and right and throws fireballs along three lanes that can only be dodged (it turns red just before a volley); killing it calls `victory()`. Dev only: `?m=1150` starts the run that many metres in.

**Weapons and coins** (`weapons.ts`, `ForestShop.ts`, `src/core/forestSave.ts`): `WEAPONS` defines pistol/shotgun/smg/laser/rocket (damage, magazine, reload, cooldown, `mode` nearest|splash|pierce, `auto`). Forest coins are a separate persistent wallet, `forestSave` in localStorage `forest-save` (coins, owned weapons, equipped one, best distance), not `progress.coins`, which `startJourney()` resets. `ForestShop` is the first forest stage and is also opened from the end-of-run screen (`{from: 'run'}`).

**Pica journey** (`PizzaMaker`, `src/scenes/minigames/pizzaData.ts`): `FishCut` (with `data.items`, a queue of texture keys, instead of `progress.fish`) cuts ingredients, then `PizzaMaker` serves 3 customers. The pizzas are real ones from the Harlekin inn menu (harlekin.si); the ones not added yet, and what ingredient each still needs, are in `TODO-pizzas.md`. A pizza is stacked 500×500 layer textures `pizza-<ingredient>` on `pizza-dough`; the customer's order bubble is built from the same layers. `check()` requires sauce then cheese first, then exactly the toppings in any order; a wrong pizza repeats the same customer.

**Translations** (`src/i18n/`): `en.ts` is the source of truth, a flat `as const` object of English-keyed strings (`'quest.bear': '🐻 Defeat bears {n}'`) and `type Key = keyof typeof en`; `sl.ts` is `Record<Key, string>`, so a missing translation fails `tsc`. `t(key, { n })` fills `{name}` placeholders. Never write player-visible text inline in a scene: add a key to both files (namespaced by area: `stage.*`, `quest.*`, `forest.*`, ...) and call `t()` inside `create()`/methods, not at module top level (the language is read at startup and can change on the Title screen). Data tables store keys, not text (`Stage.label` and `Journey.title` are `Key`s; pizza names are `pizza.${id}`), and are translated where rendered. The language comes from `?lang=sl|en` (remembered), then localStorage `lang`, then Slovene; the corner button on `Title` switches it and restarts the scene. To add a language: extend `Lang`/`LANGS` in `index.ts`, add a `Record<Key, string>` table. No plural helper yet: add one when a string needs a real count.

**Assets**: there are no image or audio files to load by hand. Every SVG in `src/art/` is auto-loaded by `Boot` (via `import.meta.glob`) as a texture keyed by its filename without extension (`src/art/monster.svg` → `'monster'`), rasterised at scale 1.5. Sound is synthesised with WebAudio in `src/core/sfx.ts`; `unlockAudio()` must be called from a user tap (iOS rule).

**Touch helpers** (`src/core/touch.ts`): `dragX`, `tapButton`, `text` — use these for large, forgiving touch targets and consistent styling. Input supports 3 simultaneous pointers.

**No offline mode**: the game used to precache everything with a service worker, but that kept serving stale builds after a new deploy, so it was removed. `public/sw.js` is only a kill switch for devices that still have the old worker (it clears caches and unregisters itself), and `src/main.ts` also unregisters leftovers. Do not register a service worker again.

**Deploy**: `.github/workflows/deploy.yml` builds and publishes `dist/` to GitHub Pages on every push to `main` (repo Settings → Pages → Source must be "GitHub Actions"). Pages serves project sites from `/<repo>/`, so the build uses `base: './'` and every URL (index.html links, manifest) must stay relative; never add root-absolute (`/foo`) URLs.
